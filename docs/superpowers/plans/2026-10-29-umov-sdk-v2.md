# Suporte à API 2.0 (JSON) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expor todas as 302 operações da API uMov.me 2.0 em `umov.v2.*`, sem alterar o uso atual da v1.

**Architecture:** Core já implementado (Tasks 0–1, commit `d704be1`): `TransportV2` (JSON, headers AppId/AppKey, retry), builders em `src/v2/resource.ts`, erros unificados, `UmovClient.v2`. Cada módulo de recurso em `src/v2/resources/<domínio>.ts` exporta DTOs + `createXxxResources(transport)` compondo os builders; `UmovV2Client` espalha os objetos retornados. Spec: [docs/superpowers/specs/2026-10-29-umov-sdk-v2-design.md](../specs/2026-10-29-umov-sdk-v2-design.md); API: [docs/api-v2.md](../../api-v2.md); DTOs: `definitions` em [docs/api-v2-openapi.json](../../api-v2-openapi.json).

**Tech Stack:** TypeScript strict, vitest, tsup. Node ≥ 18.

---

## Regras para todos os módulos (ler antes de qualquer task)

- **Modelo**: [src/v2/resources/agents.ts](../../../src/v2/resources/agents.ts) e [tests/v2/resources/agents.test.ts](../../../tests/v2/resources/agents.test.ts). Copie o estilo: DTOs no topo com `/** nome da definition — path */`, interfaces `V2XxxResource`, uma factory `createXxxResources(t: TransportV2): V2XxxResources` que devolve um objeto com **todos** os recursos do módulo.
- **Builders** (`src/v2/resource.ts`): `v2Create/v2Put/v2Patch/v2Delete(t, path, normalize?)`, `v2Link(t, path, sub)` (add/remove/put/patch em `/path/{ref}/{sub}/{subRef}`, exige refs do mesmo tipo), `v2Action(t, method, path)`, `refToV2Path(ref)`, `idOf(V2IdRef)`. Para rotas só-id use `V2IdRef`; para rotas que aceitam `/{id}` **e** `/alt-id/{alt}` use `EntityRef`.
- **DTOs**: extraia os campos da definition indicada (`node -e 'const s=require("./docs/api-v2-openapi.json"); console.log(JSON.stringify(s.definitions["<nome>"],null,1))'`). Todos os campos opcionais, exceto onde a spec marca `required` **na criação** — aí documente no JSDoc em vez de tornar obrigatório, salvo DTOs pequenos de ação (`TransferTaskDTO`, `PasswordPolicyRequest`) onde obrigatoriedade real ajuda. Tipos: `integer/number` → `number`; `boolean` → `boolean`; enum string → union literal; `Entidade de relacionamento` → `V2Ref`; `Campo customizável[]` → `V2CustomField[]`; `Dados de uma imagem` → `V2Image`; endereços → `V2AgentAddress`/`V2LocalAddress`; `[string]` → `string[]`. Mantenha os nomes de campo **exatamente** como na spec (inclusive `locais`, `aditional`, `secundary`).
- **Datas**: campos `yyyy-MM-dd` (ex.: `initialDate`, `finalDate`, `date`) tipados `V2DateInput` e normalizados com `formatDate` de `src/util/datetime.ts` via `normalize` do builder. Hora/`date-time`/`HHmmss` ficam `string`.
- **Paths duplicados** da spec: use `/locals` (não `/local`), `/tasks` (não `/task`), `/aditional-info-items`, `/password-policies` (sem `/api`).
- **Testes**: `tests/v2/resources/<domínio>.test.ts` usando `mockTransport()` de `tests/v2/helpers.ts`; **uma asserção por operação** (método + path; body quando houver normalização ou shape especial). Rode `npx vitest run tests/v2/resources/<domínio>.test.ts` e `npx tsc --noEmit`.
- Não edite `src/v2/client.ts`, `src/index.ts` nem outros módulos — o wiring é a Task 10.
- Comentários em pt-BR, curtos, como o restante do código. Sem commits (o integrador commita).

### Task 2: teams + items — `src/v2/resources/teams.ts`, `src/v2/resources/items.ts`

**teams.ts** — `createTeamResources(t): { teams }`
- DTOs: `V2Team` ← `Data object de dados da equipe` (create) e `Data object de dados da equipe e seu relacionamento com os agentes` (patch; mesmos campos — use um único `V2Team`); `V2TeamAgentRelationship` ← `Informações de relacionamento de um agente a equipe` (`{ alternativeIdentifier: string; teamResponsible?: boolean }`); `V2TeamResponsible` ← `TeamResponsibleDTO` (`{ teamResponsible?: boolean }`).
- `teams.create` POST `/team` · `teams.patch(ref)` PATCH `/team/{ref}`.
- `teams.agents.add(teamRef, agentRef, body?: V2TeamResponsible)` → POST; `.put/.patch(teamRef, agentRef, body)`; `.remove(teamRef, agentRef)`.
  **Caso especial**: por altId a rota é `/team/alt-id/{teamAlt}/agent/{agentAlt}` para POST/PUT/PATCH (agente **sem** prefixo `alt-id/`) e `/team/alt-id/{teamAlt}/agent/alt-id/{agentAlt}` para DELETE; por id é `/team/{id}/agent/{id}`. Implemente à mão (não use `v2Link`), validando refs do mesmo tipo com `assertSameRefKind`.
- `teams.agents.addByAltId(teamAltId: string, body: V2TeamAgentRelationship)` → POST `/team/alt-id/{teamAlt}/agent`.
- `teams.agents.removeAll(teamRef)` → DELETE `/team/{ref}/agents`.
- `teams.locals.add/remove(teamRef, localRef)` → `v2Link(t, 'team', 'local')`.

**items.ts** — `createItemResources(t): { items, subGroups, additionalInfoItems }`
- `V2Item` ← `Data object de dados do item`; `V2SubGroup` ← `Data object de dados do subgroup`; `V2AdditionalInfoItem` ← `AditionalInfoItemRequest` (todos obrigatórios: `active, featuredInfo, itemId, sectionId, serviceLocalId`).
- `items.create` POST `/item` · `items.upsert(body)` PUT `/item` (sem ref) · `items.put/patch(ref)` `/item/{ref}`.
- `subGroups.create` POST `/subgroup` · `put/patch(ref)` `/subgroup/{ref}`.
- `additionalInfoItems.create` POST `/aditional-info-items` · `put(ref: V2IdRef)` PUT `/aditional-info-items/{id}`.
